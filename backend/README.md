## 模块职责

本模块是整个系统的**业务与数据中枢**,负责:

1. **业务 API**:为前端(用户端 / 业务员端)提供登录、会话、车辆、订单、方案、报价、核保、支付、保单、人工转接等 REST 接口。
2. **数据持久化**:MySQL 中用户、业务员、车辆、会话、消息、订单、方案、报价、核保、支付、保单、人工转接等数据的读写。
3. **状态机**:维护订单在七个阶段中的流转(收集信息 → 智能推荐 → 身份证上传 → 报价 → 核保 → 支付 → 保单),服务端是状态的唯一权威。
4. **AI 服务中转**:调用成员 C 的 Python 智能体服务,并把智能体产生的消息、方案草稿、工具调用结果落库;智能体不直接操作业务数据库。
5. **第三方适配层**:保险公司报价/核保、第三方支付、人工接管平台统一封装为 **Adapter 接口**。当前阶段使用**模拟实现(Mock)**,严禁把模拟结果说成真实结果。
6. **鉴权与权限**:区分「用户」与「业务员」两类角色;业务员具备批量操作能力。
7. **文件与 OCR 结果管理**:接收并保存行驶证、身份证、车辆照片等影像的元数据与 OCR 结果。

## 边界与约束

- **不实现**保险公司、支付渠道的真实对接逻辑;只定义 Adapter 接口并提供 Mock 实现,真实接口资料到位后替换实现即可。
- **不伪造业务结果**:报价、核保、支付、保单的最终状态必须以服务端返回为准,前端与 AI 服务不得自行判定。
- 智能体服务**不直连数据库**,所有数据读写通过后端 API。
- 所有密钥、数据库口令只能通过**环境变量**注入,不得写入仓库。
- 接口路径统一以 `/api/v1` 开头。
