# 接口文档 — 车险出单智能体

> **状态标记**
>
> | 标记 | 含义 |
> | --- | --- |
> | ✅ **已约定** | 团队已确定,前后端 / AI 可据此开发 |
> | ⚠️ **建议待确认** | 本文给出的实施建议,需相关成员确认后才算定稿 |
> | 🔌 **待接入** | 依赖外部系统(保险公司、支付、人工平台),当前只用模拟实现 |
>
> **重要:本文不假设项目已经接入真实保险公司、支付渠道或人工接管平台。** 所有外部能力当前均为模拟,返回体中必须带 `mock: true` 与 `provider: "MOCK"`,前端不得把模拟结果显示为真实业务结果。

## 1. 通用约定

### 1.1 基础信息

| 项目 | 约定 | 状态 |
| --- | --- | --- |
| 协议 | HTTP/HTTPS | ✅ |
| 前端 ↔ 后端前缀 | `/api/v1` | ✅ |
| AI ↔ 后端内部接口前缀 | `/internal/v1` | ⚠️ 建议待确认 |
| 数据格式 | `application/json; charset=UTF-8` | ✅ |
| 文件上传 | `multipart/form-data` | ✅ |
| 字段命名 | JSON 使用 **camelCase**;数据库使用 **snake_case** | ✅ |
| 时间格式 | ISO-8601,如 `2026-11-09T10:30:00+08:00` | ✅ |
| 金额单位 | **分(整数)**,避免浮点误差;展示时前端换算为元 | ⚠️ 建议待确认 |
| 接口版本 | 路径版本 `/v1`,破坏性变更升 `/v2` | ✅ |

### 1.2 鉴权

```http
Authorization: Bearer <token>
```

- 用户与业务员使用不同角色标识,角色由服务端根据 token 判定,前端不得自行提升权限。
- 内部接口(AI → 后端)使用独立的服务令牌 `X-Internal-Token`,不得复用用户 token。⚠️ 建议待确认
- 鉴权方案(JWT / Session)尚未最终确定。⚠️ 待确认

### 1.3 统一返回结构

**成功:**

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "traceId": "a1b2c3d4e5f6"
}
```

**失败:**

```json
{
  "code": 10004,
  "message": "报价失败:该车型暂不支持在线报价",
  "data": null,
  "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 0 表示成功;非 0 见第 3 节错误码 |
| `message` | string | 面向用户的提示语,后端负责给出可读文案 |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 链路追踪 ID,排障时提供给后端 |

### 1.4 分页结构

请求参数:`page`(从 1 开始)、`pageSize`(默认 20,最大 100)。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "pageSize": 20,
    "total": 0
  },
  "traceId": "a1b2c3d4e5f6"
}
```

### 1.5 业务状态约定

业务状态一律使用**大写英文枚举**,由服务端返回,前端只做展示映射:

| 枚举 | 含义 |
| --- | --- |
| `DRAFT` | 草稿 |
| `PENDING` | 处理中 / 待用户确认 |
| `SUCCESS` / `PASSED` | 成功 / 通过 |
| `FAILED` | 失败 |
| `EXPIRED` | 已过期 |
| `CANCELLED` | 已取消 |
| `HANDOFF` | 已转人工 |

订单阶段枚举建议:
`COLLECTING_INFO` → `RECOMMENDING` → `ID_UPLOAD` → `QUOTING` → `UNDERWRITING` → `PAYING` → `POLICY_ISSUED`(⚠️ 命名待确认)。

## 2. Mock 数据标识 ✅ 已约定

凡涉及外部系统的返回,必须包含:

```json
{
  "mock": true,
  "provider": "MOCK",
  "providerRequestId": "MOCK-20261109-0001"
}
```

- `mock: true` 表示**非真实保险公司 / 支付 / 人工平台结果**。
- 前端需在界面上明确展示「演示数据」标识。
- 真实接口接入后,`provider` 改为真实渠道名,`mock` 改为 `false`。

## 3. 错误码

### 3.1 通用错误码

| code | HTTP 状态 | 含义 | 处理方 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | — |
| `40000` | 400 | 请求参数缺失或格式错误 | 前端提示并修正 |
| `40100` | 401 | 未登录或 token 失效 | 前端跳转登录 |
| `40300` | 403 | 无权限访问该资源 | 前端提示无权限 |
| `40400` | 404 | 资源不存在 | 前端提示并返回 |
| `40900` | 409 | 状态冲突(如重复报价、订单阶段不允许) | 前端刷新状态 |
| `42900` | 429 | 请求过于频繁 | 前端限流提示 |
| `50000` | 500 | 服务内部错误 | 前端提示稍后重试,后端排查 |

### 3.2 业务错误码

| code | 含义 | 前端建议处理 |
| --- | --- | --- |
| `10001` | OCR 识别失败或置信度过低 | 提示重新上传,可转人工 |
| `10002` | 车辆信息不存在(老用户查询未命中) | 提示按新用户上传行驶证 |
| `10003` | 方案不存在或不可编辑 | 刷新方案 |
| `10004` | 报价失败 | 展示失败原因,可重试 |
| `10005` | 报价已过期 | 重新发起报价 |
| `10006` | 核保不通过 | 展示原因 |
| `10007` | 核保要求补充检车照片 / 验车视频 | 跳转上传 |
| `10008` | 支付失败 | 展示原因,可重新支付 |
| `10009` | 支付结果未确认 | 轮询或提示稍后查看 |
| `10010` | 保单尚未生成 | 提示稍后查看 |
| `20001` | 会话不存在 | 返回会话列表 |
| `20002` | 会话已转人工,智能体停止应答 | 切换人工界面 |
| `30001` | 创建人工转接单失败 | 展示客服联系方式 |
| `30002` | 缺少转人工必要参数 | 检查请求 |

> 错误码新增需同步更新本表,前端不得根据 `message` 文案做业务判断,只能依据 `code`。

### 5.2 方向二:AI → 后端(智能体调用业务工具)

智能体不直连数据库,通过后端内部接口读写业务数据。需携带 `X-Internal-Token`。

| 方法 | 路径 | 说明 | 状态 |
| --- | --- | --- | --- |
| GET | `/internal/v1/sessions/{sessionId}/context` | 获取会话上下文(车辆、订单、阶段、当前方案) | ⚠️ 建议待确认 |
| POST | `/internal/v1/messages` | 保存 AI 回复消息 | ⚠️ 建议待确认 |
| GET | `/internal/v1/vehicles/lookup` | 老用户车辆查询 | ✅ |
| POST | `/internal/v1/orders/{orderId}/plans` | 创建方案草稿 | ✅ |
| PATCH | `/internal/v1/plans/{planId}` | 修改方案 | ✅ |
| POST | `/internal/v1/orders/{orderId}/quotes` | 发起报价 | ✅ |
| POST | `/internal/v1/sessions/{sessionId}/handoffs` | 创建人工转接 | ✅ |
| POST | `/internal/v1/underwritings/{id}/inspections` | 记录核保补充材料 | ⚠️ 待确认 |

> 内部接口与前端接口**共用同一套返回结构**,便于统一处理;但权限、限流、审计独立。⚠️

### 5.3 工具调用(Tool Calling)约定

智能体可调用的工具名称、参数、返回必须与后端接口一一对应,建议:

| 工具名 | 对应后端能力 |
| --- | --- |
| `lookupVehicle` | 老用户车辆查询 |
| `createPlanDraft` | 创建方案草稿 |
| `modifyPlan` | 修改方案 |
| `confirmPlan` | 用户确认方案 |
| `requestQuote` | 发起报价 |
| `submitUnderwriting` | 发起核保 |
| `createPayment` | 创建支付单 |
| `createHandoff` | 人工转接 |
| `searchKnowledge` | RAG 知识检索(智能体内部) |

> 工具参数校验由后端负责,智能体不得绕过校验直接改库。✅

### 5.4 OCR 归属(需确认)

两种方案二选一:

- **方案 A(推荐)**:智能体负责 OCR,后端只保存结果 → 需要定义 `POST /internal/v1/ocr-results`。
- **方案 B**:后端调用 OCR 服务,智能体只使用结果 → 前端上传走 `/vehicles/ocr`。

⚠️ 必须在开发前定下来,否则会出现两处 OCR 逻辑。

## 7. 接口变更流程

1. 修改接口前先在群内同步,并更新本文档。
2. 破坏性变更必须升版本或新增路径,不得直接改字段含义。
3. 新增错误码必须更新第 3 节。
4. 前端与 AI 端以本文档为准,不得私自定义字段。
5. 联调前先对照本文档逐项打勾。
