## 1. 项目定位

车险出单智能体:用户通过对话方式完成车险从信息收集到保单生成的完整流程。

- ✅ **已确定**:先做**车险**,财险、人寿险仅作为入口占位,暂不实现。
- ✅ **已确定**:系统有两类角色——**用户**与**业务员**。
- ✅ **已确定**:用户登录进入智能体时,**自带一个业务员 ID**(归属关系由登录态确定)。
- ✅ **已确定**:智能体需要外接**行业术语知识库**(RAG)。
- ✅ **已确定**:系统包含**人工接管平台**。

## 3. 七阶段完整出单流程

整体流程:

```text
收集信息 → 智能推荐 → 身份证上传 → 报价 → 核保 → 支付 → 生成保单
```

### 阶段一:收集信息

| 需求 | 状态 |
| --- | --- |
| 新用户:上传**行驶证正页 + 副页**,图片使用 OCR 识别 | ✅ 已确定 |
| 老用户:凭**车牌号**或**车架号(VIN)**查询去年信息 | ✅ 已确定 |
| 老用户可直接跳过智能推荐,进入报价 | ✅ 已确定 |
| 老用户若明确沿用去年投保方案,直接给出报价 | ✅ 已确定 |
| OCR 识别信息不正确 → 追问用户 | ✅ 已确定 |
| 追问仍无法确认 → **触发人工转接接口** | ✅ 已确定 |
| 行驶证正副页分别需要识别哪些字段 | ⚠️ 待确认(建议:车牌号、VIN、发动机号、车主、品牌型号、注册日期) |
| 老用户历史数据从何而来(真实保单系统?) | 🔌 待接入(当前用模拟数据) |

> 业务规则:会话标题使用**车牌号**命名;当对话中出现**两个不同车牌号**时,自动开启另一个会话。✅ 已确定

### 阶段二:智能推荐

| 需求 | 状态 |
| --- | --- |
| 智能体生成一套适合用户的方案 | ✅ 已确定 |

| 支持自然语言修改方案,例如「把三者险改到 200 万」 | ✅ 已确定 |
| 推荐依据(车辆信息、历史方案、险种规则) | ⚠️ 待确认 |

## 7. 关键业务规则汇总

1. ✅ 会话标题用车牌号。
2. ✅ 同一会话出现第二个车牌号时,自动新建会话。
3. ✅ 老用户可跳过智能推荐直接报价。
4. ✅ 老用户沿用去年方案时直接报价。
5. ✅ 方案价格以服务端报价为准。
6. ✅ 业务员可批量操作流程,用户不可。
7. ✅ 当前只支持车险。
8. ✅ 状态以服务端为准,前端与智能体不得自行判定成功。
9. ⚠️ 一个会话是否只能对应一个订单 / 一辆车,待确认。
10. ⚠️ 用户在流程中途退出后如何恢复,待确认。
