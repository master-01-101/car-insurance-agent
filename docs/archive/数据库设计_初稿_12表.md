# 数据库设计 — 车险出单智能体

> **状态标记**
>
> | 标记 | 含义 |
> | --- | --- |
> | ✅ **已确定** | 表/字段为业务明确需要 |
> | ⚠️ **待确认** | 建议设计,需团队确认字段、宽度或枚举 |

> **说明:** 本文是**建议设计**,不是最终定稿。当前没有真实保险公司 / 支付 / 人工平台接口,相关表只保存模拟返回,并用 `is_mock` 标记。字段类型以 MySQL 8 为准。

## 1. 通用约定

| 项目 | 约定 |
| --- | --- |
| 存储引擎 | InnoDB |
| 字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT` |
| 时间字段 | `created_at`、`updated_at` `DATETIME(3)` |
| 逻辑删除 | `deleted TINYINT NOT NULL DEFAULT 0`(仅主数据表使用) |
| 金额 | **BIGINT,单位:分**(避免浮点误差) ✅ 接口层待确认 |
| 布尔 | `TINYINT(1)`,1=是,0=否 |
| 枚举 | 使用 `VARCHAR`,配合应用层枚举校验(便于扩展) |
| 表名 | `snake_case` 单数;避开 MySQL 保留字(`order` → `insurance_order`) |
| 外键 | **逻辑外键**(应用层保证),是否建物理外键 ⚠️ 待确认 |
| 时区 | 统一存 `+08:00` 东八区,接口返回带时区 |

## 2. 表关系总览

```text
staff 1 ──────< app_user          (业务员归属用户)
app_user 1 ───< vehicle           (一个用户多辆车)
app_user 1 ───< conversation      (一个用户多个会话)
vehicle 1 ────< conversation      (会话绑定车辆)
conversation 1 < message          (会话多条消息)
conversation 1 ─< insurance_order (会话生成订单)
insurance_order 1 < plan          (订单多个方案版本)
plan 1 ──────< quote              (方案多次报价)
quote 1 ─────< underwriting       (报价对应核保,可能重试)
insurance_order 1 < payment       (订单可能多次支付)
insurance_order 1 ─ policy        (成功出单后一张保单)
conversation 1 ─< handoff         (会话可多次转人工)
```

> 一个会话对应一个订单、一辆车,属于 ⚠️ 待确认规则(原文未明确)。

## 5. 建表注意事项

1. **敏感信息**:身份证号、手机号等按最小必要原则存储;身份证号必须加密,展示一律脱敏 ✅。
2. **金额**:全部用 `BIGINT` 存「分」,禁止 `FLOAT` / `DOUBLE` ✅。
3. **幂等**:`message.client_message_id`、`payment.pay_no`、`quote.quote_no` 用于防重复处理 ✅。
4. **状态机**:订单阶段与状态变更必须由后端统一校验,禁止跳阶段 ✅。
5. **快照**:保单保存车辆、人员快照,不直接引用会变化的用户资料 ✅。
6. **模拟数据**:所有外部系统结果必须写 `is_mock=1` 与 `provider='MOCK'`,真实接入后回填真实值 🔌。
7. **索引**:以外键查询、时间排序、状态筛选为主;上线前用 `EXPLAIN` 检查慢查询 ⚠️。
8. **字符集**:表与连接统一 `utf8mb4`,避免车牌、姓名中的特殊字符乱码 ✅。
