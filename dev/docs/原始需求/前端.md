**车险出单智能体项目任务书**

成员 A｜前端开发与用户交互负责人

# 文档使用说明

本任务书依据《车险出单需求.docx》整理。需求文档明确的业务包括：用户/业务员两类角色、当前先实现车险、新老用户车辆信息收集、智能推荐及自然语言修改、身份证影像上传、报价、核保、支付、保单明细、车牌号会话标题、业务员批量操作、行业术语知识库和人工接管平台。

下文中的技术选型、数据库字段、接口路径、状态枚举、模拟服务和排期均属于团队实施建议，不是原需求文档已经提供的接口或现成能力。真实保险公司报价/核保、第三方支付及人工接管平台的接口资料，需要项目方另行提供；在没有真实接口前，应明确标注为模拟数据和演示流程。

# 一、岗位目标与职责边界

岗位目标：完成用户端和业务员端的前端页面，使用户可以通过网页完成车险办理流程，并能清晰查看每一步的状态和结果。

- 负责前端工程搭建、页面布局、交互逻辑、状态展示、文件上传和接口联调。
- 不直接访问或修改数据库；所有业务数据通过成员 B 提供的后端 API 获取和提交。
- 不在前端自行判断报价、核保、支付是否成功；以服务端返回的业务状态为准。
- 与成员 C 对齐聊天消息、工具执行结果、追问、人工接管等 AI 交互协议。

# 二、建议技术栈与工程结构

| **项目项** | **建议方案**              | **说明**                                                        |
| ---------- | ------------------------- | --------------------------------------------------------------- |
| 框架       | React + TypeScript + Vite | 如团队已有 Vue 技术基础，也可统一使用 Vue；不要中途频繁换框架。 |
| UI 组件    | Ant Design                | 表单、上传、表格、步骤条、弹窗等可复用组件。                    |
| 请求层     | Axios 或 Fetch            | 统一处理 token、错误提示、接口响应。                            |
| 聊天呈现   | 自定义 Chat 组件          | 支持文本、图片、方案卡片、业务状态卡片。                        |
| 实时输出   | 先普通 HTTP，后续可选 SSE | 先保证可用，再做流式输出。                                      |

```
frontend/
  src/
    api/          # 按业务模块封装接口
    components/   # 上传组件、聊天气泡、方案卡片
    pages/        # 登录、聊天、订单、保单、业务员工作台
    router/       # 路由与权限
    store/        # 登录态、当前会话、当前车辆
    types/        # 与后端约定的 TypeScript 类型
    utils/        # 文件校验、格式化等
```

# 三、页面与功能任务拆分

| **模块**     | **具体开发内容**                                                | **验收标准**                                           |
| ------------ | --------------------------------------------------------------- | ------------------------------------------------------ |
| 登录与身份   | 登录页；保存登录凭证；识别普通用户/业务员角色；按角色显示菜单。 | 登录成功后进入正确工作台；无权限页面不能直接访问。     |
| 车险入口     | 展示车险入口；财险、人寿险可展示为暂未开放或不展示。            | 当前版本只允许进入车险流程。                           |
| 会话列表     | 展示会话；会话标题显示车牌号；新建会话、切换会话。              | 不同车牌号可对应不同会话；刷新后列表仍可加载。         |
| 聊天界面     | 消息气泡、输入框、发送、加载状态、错误提示、历史消息。          | 用户消息和 AI 回复顺序正确；切换会话不串消息。         |
| 行驶证上传   | 上传正页和副页；显示上传进度、预览、删除/重传。                 | 缺少必要图片时提示；上传结果能关联当前车辆/会话。      |
| OCR 结果确认 | 展示识别字段；标记缺失/异常字段；允许用户确认或修正。           | 确认后的字段提交后端；不把 OCR 结果默认视为最终正确。  |
| 保险方案     | 展示保险公司、险种、保额、价格；支持用户通过聊天提出修改。      | 修改后刷新展示后端确认的方案版本。                     |
| 身份证上传   | 正反面上传；展示影像状态和关键信息确认。                        | 图片与当前投保订单关联；页面不暴露不必要的完整证件号。 |
| 报价与核保   | 展示报价状态、报价明细、核保通过/失败、补充验车材料入口。       | 不同状态展示正确操作；失败原因能看懂。                 |
| 支付与保单   | 展示支付入口/模拟支付结果；支付成功后展示保单明细。             | 只有后端确认支付成功后才展示已支付/已出单。            |
| 业务员工作台 | 客户/车辆/订单列表；多选；批量提交允许的操作。                  | 仅业务员角色可见；批量操作有结果反馈。                 |
| 人工接管展示 | 显示转人工状态、处理进度、人工回复。                            | AI 接管状态和人工处理状态一致。                        |

# 四、前端与其他成员的接口协作

- 第一周与成员 B 确认登录、车辆、会话、消息、订单等 API 的 URL、请求字段、响应字段和错误码。
- 与成员 C 确认聊天接口返回结构：普通文本、需要用户确认的方案、上传材料要求、转人工提示等如何区分。
- 所有页面使用统一 API 封装，不在页面组件中散落硬编码 URL。
- 接口未完成时可使用 Mock 数据开发，但必须标记 Mock；联调时切换为真实后端接口。

# 六、四周工作计划

| **周期** | **任务**                                                              | **阶段交付**                               |

# 七、每日工作与沟通要求

- 每天开始前确认当天要完成的页面/组件；结束时提交代码并说明完成情况。
- 遇到接口字段不明确时先在群里确认，不自行猜字段。
- 每次合并前至少完成页面自测；提交时写清楚改动模块和测试方式。
- 每周至少两次三人联调：一次核对接口，一次跑通业务流程。
