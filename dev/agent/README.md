## 模块职责

本模块是车险出单流程的**对话与智能决策层**,负责:

1. **对话编排**:理解用户自然语言,按七个阶段推进业务(收集信息 → 智能推荐 → 身份证上传 → 报价 → 核保 → 支付 → 保单),在正确时机提示用户下一步操作。
2. **工具调用(Tool / Function Calling)**:调用后端提供的工具接口,例如查询老用户车辆信息、生成方案草稿、发起报价、创建人工转接单等。
3. **OCR 调度**:对行驶证正副页、身份证正反面进行识别,把结构化结果交给后端校验;识别失败或信息不一致时触发追问。
4. **智能推荐**:结合车辆信息、历史方案与险种规则,生成「保险公司 + 险种 + 保额 + 价格」的方案草稿;**保费价格以后端/报价服务返回为准**,智能体不自行计算保费。
5. **自然语言改方案**:支持类似「把三者险改到 200 万」的指令,修改方案草稿后重新请求报价。
6. **RAG 知识库**:检索行业术语与通俗表达的对齐关系,帮助理解用户口语化描述。
7. **人工转接**:在 OCR 信息无法确认、用户主动要求、或异常情况下,调用后端接口创建人工转接单,并停止自动应答。
8. **流式输出**:向前端推送 AI 回复过程(先普通 HTTP,后续可选 SSE)。


## 边界与约束

- **不直接连接业务数据库**,所有业务数据通过后端 API 读写。
- **不自行计算保费、不伪造核保/支付结果**;价格与状态以后端返回为准。
- 大模型密钥、OCR 密钥只能放环境变量,`.env` 不入库,`.env.example` 入库。
- 所有对外输出的业务状态需带来源标识,避免前端把模拟数据当成真实数据。
- 与后端的调用协议以 `docs/接口文档.md` 为准,变更协议需同步文档并通知两端。
